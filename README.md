## 🔬 My Engineering Approach

I approach each problem with a structured workflow inspired by good software engineering practices.

**01 — Understand**

Read the problem carefully, identify the inputs and outputs, and understand all constraints.

**02 — Analyze**

Explore examples, identify edge cases, and determine which data structures or algorithmic patterns may apply.

**03 — Implement**

Start with a correct solution and use clean, readable JavaScript.

**04 — Optimize**

Evaluate alternative approaches and reduce unnecessary time or space complexity where possible.

**05 — Validate**

Test sample inputs, boundary conditions, and additional edge cases.

**06 — Document**

Record the reasoning, complexity, mistakes, and key takeaways for future revision.

### 📊 Complexity Matters

Every solution should aim for correctness first, followed by an appropriate balance of performance, readability, and maintainability.

| Complexity | What it measures |
|---|---|
| `O(1)` | Constant time |
| `O(log n)` | Logarithmic time |
| `O(n)` | Linear time |
| `O(n log n)` | Linearithmic time |
| `O(n²)` | Quadratic time |

These are common complexity classes, not performance guarantees for every implementation.
